# Clever PGP

Clever PGP — локальное автономное приложение для криптографической защиты файлов и дисков с биометрическим управлением.

Проект является бесплатным и открытым программным обеспечением под лицензией
GNU General Public License версии 3 или более поздней. Clever PGP не требует
покупки, подписки или сервера активации.

Тема диссертации:

> «Метод криптографической защиты файлов с биометрическим управлением на основе распознавания лица».

## Границы продукта

Clever PGP защищает только выбранные пользователем данные:

- отдельный файл преобразуется в самостоятельный зашифрованный файл `.cpgp`;
- зашифрованный диск хранится в обычном файле-контейнере `.cpgv` и после
  разблокировки подключается как виртуальный диск.

Clever PGP не шифрует Windows, диск `C:`, системные или загрузочные разделы,
физические накопители, EFI-раздел и загрузчик. В программе нет предзагрузочной
аутентификации и шифрования операционной системы; добавление этих функций не
планируется. Блочный модуль принимает только обычные файлы `.cpgv` и отвергает
пути устройств Windows. Форматирование разрешается только для только что
подключённого виртуального устройства Clever PGP после проверки его размера,
идентификаторов, единственного раздела и отсутствия признаков системного или
загрузочного диска.

## Что уже работает в MVP

- первое окно на PySide6/Qt;
- создание одного локального профиля;
- генерация случайного 256-битного мастер-ключа;
- защита мастер-ключа ключом, полученным из мастер-пароля через Argon2id;
- локальное хранение зашифрованного мастер-ключа и настроек профиля в SQLite;
- потоковое шифрование и расшифрование файлов в формате `.cpgp`;
- отдельная случайная асимметричная идентичность профиля: закрытые ключи
  зашифрованы мастер-ключом, а открытые ключи можно экспортировать в `.cpgk`;
- книга локальных контактов с проверкой самоподписи импортируемого `.cpgk` и
  обязательной ручной сверкой полного отпечатка по независимому каналу;
- шифрование одного файла сразу для владельца и выбранных контактов: содержимое
  преобразуется один раз, а случайный ключ файла независимо защищается для
  каждого получателя;
- потоковая цифровая подпись каждого `.cpgp`; после расшифрования программа
  различает собственную подпись, известный контакт и математически верную
  подпись ещё не подтверждённого отправителя;
- аутентифицированное шифрование через libsodium: файлы используют переносимый
  XChaCha20-Poly1305, а для новых обычных дисков пользователь может выбрать
  XChaCha20-Poly1305 или доступный на процессоре AES-256-GCM;
- обнаружение неправильного ключа, повреждения и подмены шифротекста;
- атомарная запись результата: незавершённый расшифрованный файл не выдаётся пользователю;
- четыре режима разблокировки заложены в модель профиля.
- команда «Зашифровать с Clever PGP» в контекстном меню файлов Windows;
- открытие и расшифрование `.cpgp` двойным щелчком или через контекстное меню;
- открытие `.cpgk` двойным щелчком в компактном окне с именем и полным
  выделяемым отпечатком перед добавлением ключа в контакты;
- оригинальный файл после шифрования не удаляется и не изменяется.
- создание зашифрованного контейнера `.cpgv` выбранной пользователем ёмкости;
- научно описанный выбор метода шифрования при создании обычного диска:
  переносимый программный режим рекомендуется по умолчанию, а аппаратно
  ускоряемый режим предлагается только после локальной проверки поддержки;
- изменение метода шифрования уже подключённого обычного WinSpd-диска из
  контекстного меню Проводника: диск безопасно отключается, каждый блок
  аутентифицируется и записывается во временный образ с новым случайным ключом
  тома, весь результат повторно читается и сравнивается с исходным, после чего
  контейнер атомарно заменяется и диск подключается снова; при ошибке исходный
  файл сохраняется, а прежний диск автоматически открывается повторно;
- создание нового скрытого диска внутри `.cpgv`: внешний и скрытый диски имеют
  разные пароли, а введённый пароль определяет, какой из них подключается;
- при открытии внешнего диска можно дополнительно ввести пароль скрытого диска,
  чтобы блокировать запись в его область; скрытый диск не добавляется в уже
  используемый контейнер без достоверной проверки свободного места;
- пароль подключённого внешнего или скрытого диска можно изменить из его
  контекстного меню без перешифрования файлов; перед обновлением заголовка диск
  безопасно отключается, а после завершения открывается новым паролем;
- горизонтальный ползунок ёмкости от 1 МБ до доступного максимума выбранного накопителя без искусственного лимита 512 МБ;
- папки, имена и содержимое контейнера зашифрованы, целостность проверяется;
- контейнер заранее проверяет свободное место и показывает процент подготовки каждого зашифрованного блока;
- при копировании преобразуются только затронутые блоки, а не весь контейнер;
- быстрый WinSpd-диск объединяет последовательные физические чтения и использует
  системный кэш страниц только для шифротекста контейнера; мелкие запросы NTFS
  не создают отдельную буферизованную файловую операцию на каждый блок, а
  запросы синхронизации Windows по-прежнему принудительно сохраняются; размер
  передачи ограничен 64 КиБ, а два диспетчерских потока не создают десятки
  конкурирующих Python-вызовов на многопроцессорных компьютерах;
- два чередующихся состояния метаданных позволяют вернуться к предыдущему завершённому состоянию после прерванного сохранения;
- отключённый блочный контейнер можно безопасно увеличить без перешифрования существующих блоков; новый размер подтверждается трёхслотовым журналом заголовка и не публикуется при прерванной операции;
- подключение контейнера как отдельной буквы диска через WinFsp;
- при создании нового диска интерфейс предлагает быстрый виртуальный диск Windows первым и сохраняет универсальный WinFsp-вариант; недоступный на компьютере backend не предлагается;
- открытие `.cpgv` двойным щелчком с запросом разрешённого профилем фактора;
- после разблокировки программа аутентифицирует только защищённый заголовок `.cpgv` и автоматически выбирает виртуальный WinSpd-диск или WinFsp-диск; формат не преобразуется, а содержимое пользовательских файлов для выбора не читается;
- копирование обычных файлов на подключённый диск с автоматическим шифрованием;
- локальная регистрация и проверка лица с активной liveness-проверкой;
- безопасная смена мастер-пароля без изменения мастер-ключа и без повторного шифрования существующих файлов и контейнеров;
- изменение режима разблокировки с запретом включать обязательную биометрию до регистрации лица;
- скрытый аварийный вход по мастер-паролю в режиме «Только лицо» без отдельного recovery-файла;
- безопасное отключение диска с сохранением контейнера;
- числовой прогресс создания диска, подключения, шифрования и расшифрования;
- сообщения об успешных операциях показываются внутри окна без всплывающих диалогов.
- главное окно всегда запускается развёрнутым на весь рабочий экран.
- главное окно использует две широкие панели без полосы прокрутки.
- окно входа расположено по центру, а основные действия снабжены визуальными иконками.
- команды «Открыть», «Сведения о диске», «Настройки доступа», «Изменить пароль диска», «Увеличить диск» и «Отключить» публикуются в контекстном меню активного виртуального диска только для поддерживающих их форматов; отдельное компактное окно сведений показывает ёмкость, файловую систему и научное описание защиты без пароля, биометрических данных или ключей;
- «Настройки доступа» из Проводника открывают только компактную аутентификацию и окно профиля, не показывая главную панель; выбранная буква сверяется с живым диском, а закрытие окна не отключает диск;
- динамическое меню виртуального диска ограничивается его активной буквой и удаляется после отключения, а команда сведений повторно проверяет живой аутентифицированный канал перед чтением параметров;
- виртуальный диск обслуживается самостоятельным скрытым host-процессом: GUI можно завершить через область уведомлений, не отключая уже открытый диск.
- после повторного запуска GUI находит уже работающий виртуальный диск через защищённый локальный канал и снова предоставляет команды открытия и безопасного отключения.
- первое форматирование нового виртуального диска подготовлено через отдельный минимальный UAC-процесс: он получает только DPAPI-защищённый одноразовый токен, параметры и название нового виртуального диска, дважды проверяет живой host и повторно сверяет точную идентичность устройства; мастер-пароль, мастер-ключ и биометрические данные ему не передаются;
- увеличение виртуального диска NTFS запускается из Проводника в компактном окне: контейнер растёт без перешифрования прежних блоков, а отдельный UAC-процесс принимает одноразовый аутентифицированный запрос, дважды проверяет host и не получает пароль или ключ;
- интерфейс доступен на English, Русском и Қазақша; выбранный язык сохраняется локально;
- переводы хранятся в отдельных каталогах, поэтому новые языки можно добавлять без изменения криптографической логики.

Биометрия лица, активная liveness-проверка и слот, защищённый средствами Windows, работают локально. Лицо не используется как криптографический ключ. Отдельный recovery key не создаётся.

> Это исследовательский MVP, а не прошедший независимый аудит продукт. Не используйте его для единственной копии важных данных.

## Установка на Windows

Для обычного пользователя предназначен единый файл `Clever-PGP-Setup-0.12.0.exe`. Установщик сам:

- устанавливает Clever PGP со всеми библиотеками — отдельный Python не нужен;
- устанавливает системный компонент WinFsp для виртуального диска;
- устанавливает официальный WinSpd для быстрого виртуального диска Windows;
- создаёт ярлык в меню «Пуск» и по желанию на рабочем столе;
- добавляет шифрование, расшифрование, импорт открытых ключей и подключение
  зашифрованных дисков в Проводник;
- предлагает сразу запустить Clever PGP.

Командная строка пользователю не требуется. Установщик запрашивает права администратора, потому что WinFsp, WinSpd и интеграция с Проводником устанавливаются для всей системы.

Проверенные версии публикуются на
[странице GitHub Releases](https://github.com/zti-kz/cleverpgp/releases).
Выпуск содержит Windows-установщик, отдельный файл SHA-256 и автоматически
сформированные архивы исходного кода. Для будущих тегов `vX.Y.Z` GitHub
Actions сначала сверяет номера версии, запускает тесты, собирает установщик и
выполняет проверки упакованного приложения. Только после этих этапов создаётся
публичный релиз; для установщика также формируется подписанное GitHub-свидетельство
происхождения сборки.

Каталог для готового установщика можно указать при сборке. Для рабочих сборок
проекта используется `E:\Clever\_PGP`:

```powershell
.\build_installer.ps1 -OutputDirectory "E:\Clever\_PGP"
```

Текущая исследовательская сборка ещё не подписана коммерческим сертификатом издателя, поэтому Windows SmartScreen может показать предупреждение. Перед публичным распространением установщик и основной EXE нужно подписать сертификатом code signing.

После получения сертификата Code Signing сборка умеет автоматически подписывать
`CleverPGP.exe` и готовый установщик с SHA-256 и доверенной меткой времени. Сертификат
должен находиться в хранилище Windows или на поддерживаемом аппаратном носителе.
Сборка принимает только действующий сертификат для подписи программ, имя которого
точно совпадает с `Almas Oskenbay`. Пароль и закрытый ключ в проект не записываются:

```powershell
$env:BIOPGP_SIGNTOOL = "C:\Program Files (x86)\Windows Kits\10\bin\<версия>\x64\signtool.exe"
$env:BIOPGP_SIGN_CERT_SHA1 = "ОТПЕЧАТОК_СЕРТИФИКАТА"
$env:BIOPGP_TIMESTAMP_URL = "http://time.certum.pl"
.\build_installer.ps1
```

Путь к `signtool.exe` и адрес метки времени Sectigo определяются автоматически;
их переменные нужны только для переопределения. Без отпечатка сертификата установщик
по-прежнему собирается, но остаётся неподписанным. Подробная процедура приведена в
[docs/CODE_SIGNING.md](docs/CODE_SIGNING.md).

Сборка установщика разработчиком:

```powershell
.\build_installer.ps1
```

Готовый единый EXE появится в `release`.

## Запуск из исходного кода для разработки

Для подготовки среды разработки можно запустить `install.cmd`. Один установочный сценарий:

- устанавливает Python 3.14, если его ещё нет;
- создаёт отдельное окружение Clever PGP;
- устанавливает PySide6, PyNaCl/libsodium, OpenCV, NumPy и FUSE-адаптер;
- загружает и проверяет локальные модели лица;
- устанавливает WinFsp для виртуального диска;
- добавляет команды Clever PGP в Проводник;
- в конце проверяет импорт всех компонентов.

Установщики Python и WinFsp загружаются только с официальных источников и проверяются по закреплённым SHA-256. Для WinFsp Windows покажет стандартный запрос прав администратора. Повторный запуск безопасен: уже установленные и проверенные компоненты пропускаются.

Альтернативный запуск установки из PowerShell:

```powershell
.\setup.ps1
```

После установки:

```powershell
.\run.ps1
```

Если политика PowerShell запрещает запуск скриптов:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m biopgp
```

Тесты:

```powershell
.\.venv\Scripts\python.exe -m pytest
```

`setup.ps1` также устанавливает контекстное меню только для текущего пользователя Windows. Права администратора не требуются. В Windows 11 команда может находиться в пункте «Показать дополнительные параметры».

Для подключения `.cpgv` как диска нужен системный компонент WinFsp. Основной `install.cmd` устанавливает его автоматически. Кнопка в главном окне и отдельный сценарий остаются для восстановления компонента:

```powershell
.\install_virtual_disk.ps1
```

После установки WinFsp перезапустите Clever PGP. Отдельное шифрование `.cpgp` от WinFsp не зависит.

Блочный backend WinSpd проходит автоматическую проверку в отдельном фоновом
процессе и входит в сборку. Проверены операции чтения, записи и внешнего
отключения. Если компонент установлен, окно создания предлагает быстрый
виртуальный Windows-диск первым; WinFsp-backend остаётся рабочим вариантом для
собственной файловой системы Clever PGP. Первое форматирование использует
отдельный запрос UAC и требует подтверждения пользователя Windows.

Установщик принимает официальные пакеты WinFsp и WinSpd только при совпадении
закреплённой контрольной суммы и действительной цифровой подписи их издателя.

Переустановить или удалить интеграцию вручную:

```powershell
.\install_context_menu.ps1
.\uninstall_context_menu.ps1
```

Локальная база по умолчанию находится в `%LOCALAPPDATA%\BioPGP\biopgp.sqlite3`. Пароль в базе не хранится. В ней находятся соль Argon2id, параметры KDF и зашифрованный мастер-ключ.

## Текущий криптографический формат

Каждый файл получает независимый случайный ключ. Данные шифруются потоковым XChaCha20-Poly1305, а ключ файла оборачивается мастер-ключом профиля с помощью SecretBox. Заголовок и каждый блок аутентифицируются.

Подробности и границы модулей описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
Правила безопасной публикации, подписи и сообщения об уязвимостях описаны в
[SECURITY.md](SECURITY.md).

## Два независимых сценария

Файловый сценарий повторяет привычную модель GpgEX: выбранный файл остаётся на месте, а рядом создаётся отдельный зашифрованный файл. Пока Clever PGP шифрует для собственного локального профиля. Выбор получателя по открытому ключу, подпись и несколько выбранных файлов будут добавлены после формирования ключевой пары и раздела контактов.

Контейнерный сценарий работает подобно VeraCrypt на уровне взаимодействия: Clever PGP создаёт один файл `.cpgv`, подключает его как отдельный диск, а пользователь копирует существующие файлы внутрь. Это собственный формат Clever PGP, не совместимый с VeraCrypt.

Формат контейнера v3 хранит данные независимыми аутентифицированными логическими блоками. Запись файла изменяет только соответствующие блоки; номер блока криптографически связан с его шифротекстом, поэтому перестановка или подмена обнаруживается. Метаданные файловой системы записываются в два чередующихся контрольных состояния. Новое состояние становится рабочим только после полной синхронизации, а при прерванной записи остаётся предыдущее завершённое состояние. Открытая временная папка на диске не создаётся. Старые форматы `.cpgv` не поддерживаются.
