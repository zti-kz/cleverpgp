# Clever PGP

Clever PGP — локальное автономное приложение для криптографической защиты файлов и дисков с биометрическим управлением.

Проект является бесплатным и открытым программным обеспечением под лицензией
GNU General Public License версии 3 или более поздней. Clever PGP не требует
покупки, подписки или сервера активации.

Тема диссертации:

> «Метод криптографической защиты файлов с биометрическим управлением на основе распознавания лица».

## Что уже работает в MVP

- первое окно на PySide6/Qt;
- создание одного локального профиля;
- генерация случайного 256-битного мастер-ключа;
- защита мастер-ключа ключом, полученным из мастер-пароля через Argon2id;
- локальное хранение зашифрованного мастер-ключа и настроек профиля в SQLite;
- потоковое шифрование и расшифрование файлов в формате `.cpgp`;
- аутентифицированное шифрование XChaCha20-Poly1305 через libsodium;
- обнаружение неправильного ключа, повреждения и подмены шифротекста;
- атомарная запись результата: незавершённый расшифрованный файл не выдаётся пользователю;
- четыре режима разблокировки заложены в модель профиля.
- команда «Зашифровать с Clever PGP» в контекстном меню файлов Windows;
- открытие и расшифрование `.cpgp` двойным щелчком или через контекстное меню;
- оригинальный файл после шифрования не удаляется и не изменяется.
- создание зашифрованного контейнера `.cpgv` выбранной пользователем ёмкости;
- горизонтальный ползунок ёмкости от 1 МБ до доступного максимума выбранного накопителя без искусственного лимита 512 МБ;
- папки, имена и содержимое контейнера зашифрованы, целостность проверяется;
- контейнер заранее проверяет свободное место и показывает процент подготовки каждого зашифрованного блока;
- при копировании преобразуются только затронутые блоки, а не весь контейнер;
- два чередующихся состояния метаданных позволяют вернуться к предыдущему завершённому состоянию после прерванного сохранения;
- отключённый блочный контейнер можно безопасно увеличить без перешифрования существующих блоков; новый размер подтверждается трёхслотовым журналом заголовка и не публикуется при прерванной операции;
- подключение контейнера как отдельной буквы диска через WinFsp;
- открытие `.cpgv` двойным щелчком с запросом разрешённого профилем фактора;
- копирование обычных файлов на подключённый диск с автоматическим шифрованием;
- локальная регистрация и проверка лица с активной liveness-проверкой;
- безопасная смена мастер-пароля без изменения мастер-ключа и без повторного шифрования существующих файлов и контейнеров;
- изменение режима разблокировки с запретом включать обязательную биометрию до регистрации лица;
- скрытый аварийный вход по мастер-паролю в режиме «Только лицо» без отдельного recovery-файла;
- безопасное отключение диска с сохранением контейнера;
- числовой прогресс создания диска, подключения, шифрования и расшифрования;
- сообщения об успешных операциях показываются внутри окна без всплывающих диалогов.
- главное окно всегда запускается развёрнутым на весь рабочий экран.
- главное окно использует две широкие панели без полосы прокрутки.
- окно входа расположено по центру, а основные действия снабжены визуальными иконками.
- команды «Открыть», «Сведения о диске», «Настройки доступа» и «Отключить» доступны в контекстном меню подключённого диска; отдельное компактное окно сведений показывает ёмкость, файловую систему и научное описание защиты без пароля, биометрических данных или ключей;
- динамическое меню системного диска ограничивается его активной буквой и удаляется после отключения, а команда сведений повторно проверяет живой аутентифицированный канал перед чтением параметров;
- системный диск обслуживается самостоятельным скрытым host-процессом: GUI можно завершить через область уведомлений, не отключая уже открытый диск.
- после повторного запуска GUI находит уже работающий системный диск через защищённый локальный канал и снова предоставляет команды открытия и безопасного отключения.
- подготовлено безопасное увеличение системного диска NTFS: контейнер растёт без перешифрования прежних блоков, а отдельный UAC-процесс повторно проверяет точный диск и не получает пароль или ключ; команда будет добавлена в Проводник после реального испытания на временном диске;
- интерфейс доступен на English, Русском и Қазақша; выбранный язык сохраняется локально;
- переводы хранятся в отдельных каталогах, поэтому новые языки можно добавлять без изменения криптографической логики.

Биометрия лица, активная liveness-проверка и защищённый системный слот Windows работают локально. Лицо не используется как криптографический ключ. Отдельный recovery key не создаётся.

> Это исследовательский MVP, а не прошедший независимый аудит продукт. Не используйте его для единственной копии важных данных.

## Установка на Windows

Для обычного пользователя предназначен единый файл `Clever-PGP-Setup-0.5.7.exe`. Установщик сам:

- устанавливает Clever PGP со всеми библиотеками — отдельный Python не нужен;
- устанавливает системный компонент WinFsp для виртуального диска;
- устанавливает официальный WinSpd для будущего штатно форматируемого диска Windows;
- создаёт ярлык в меню «Пуск» и по желанию на рабочем столе;
- добавляет шифрование и расшифрование в контекстное меню Проводника;
- предлагает сразу запустить Clever PGP.

Командная строка пользователю не требуется. Установщик запрашивает права администратора, потому что WinFsp, WinSpd и интеграция с Проводником устанавливаются для всей системы.

Каталог для готового установщика можно указать при сборке. Для рабочих сборок
проекта используется `E:\Clever\_PGP`:

```powershell
.\build_installer.ps1 -OutputDirectory "E:\Clever\_PGP"
```

Текущая исследовательская сборка ещё не подписана коммерческим сертификатом издателя, поэтому Windows SmartScreen может показать предупреждение. Перед публичным распространением установщик и основной EXE нужно подписать сертификатом code signing.

После получения сертификата Code Signing сборка умеет автоматически подписывать
`CleverPGP.exe` и готовый установщик с SHA-256 и доверенной меткой времени. Сертификат
должен находиться в хранилище Windows или на поддерживаемом аппаратном носителе.
Пароль и закрытый ключ в проект не записываются:

```powershell
$env:BIOPGP_SIGNTOOL = "C:\Program Files (x86)\Windows Kits\10\bin\<версия>\x64\signtool.exe"
$env:BIOPGP_SIGN_CERT_SHA1 = "ОТПЕЧАТОК_СЕРТИФИКАТА"
$env:BIOPGP_TIMESTAMP_URL = "АДРЕС_МЕТКИ_ВРЕМЕНИ_ОТ_ПОСТАВЩИКА"
.\build_installer.ps1
```

Без этих настроек установщик по-прежнему собирается, но остаётся неподписанным.

Сборка установщика разработчиком:

```powershell
.\build_installer.ps1
```

Готовый единый EXE появится в `release`.

## Запуск из исходного кода для разработки

Для подготовки среды разработки можно запустить `install.cmd`. Один установочный сценарий:

- устанавливает Python 3.14, если его ещё нет;
- создаёт отдельное окружение Clever PGP;
- устанавливает PySide6, PyNaCl/libsodium, OpenCV, NumPy и FUSE-адаптер;
- загружает и проверяет локальные модели лица;
- устанавливает WinFsp для виртуального диска;
- добавляет команды Clever PGP в Проводник;
- в конце проверяет импорт всех компонентов.

Установщики Python и WinFsp загружаются только с официальных источников и проверяются по закреплённым SHA-256. Для WinFsp Windows покажет стандартный запрос прав администратора. Повторный запуск безопасен: уже установленные и проверенные компоненты пропускаются.

Альтернативный запуск установки из PowerShell:

```powershell
.\setup.ps1
```

После установки:

```powershell
.\run.ps1
```

Если политика PowerShell запрещает запуск скриптов:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m biopgp
```

Тесты:

```powershell
.\.venv\Scripts\python.exe -m pytest
```

`setup.ps1` также устанавливает контекстное меню только для текущего пользователя Windows. Права администратора не требуются. В Windows 11 команда может находиться в пункте «Показать дополнительные параметры».

Для подключения `.cpgv` как диска нужен системный компонент WinFsp. Основной `install.cmd` устанавливает его автоматически. Кнопка в главном окне и отдельный сценарий остаются для восстановления компонента:

```powershell
.\install_virtual_disk.ps1
```

После установки WinFsp перезапустите Clever PGP. Отдельное шифрование `.cpgp` от WinFsp не зависит.

Новый блочный backend WinSpd уже проходит автоматическую проверку в отдельном
фоновом процессе и входит в сборку. Проверены операции чтения, записи и внешнего
отключения; новые привилегированные операции публикуются в интерфейсе только
после отдельного реального испытания с UAC. WinFsp-backend остаётся рабочим
вариантом для собственной файловой системы Clever PGP.

Переустановить или удалить интеграцию вручную:

```powershell
.\install_context_menu.ps1
.\uninstall_context_menu.ps1
```

Локальная база по умолчанию находится в `%LOCALAPPDATA%\BioPGP\biopgp.sqlite3`. Пароль в базе не хранится. В ней находятся соль Argon2id, параметры KDF и зашифрованный мастер-ключ.

## Текущий криптографический формат

Каждый файл получает независимый случайный ключ. Данные шифруются потоковым XChaCha20-Poly1305, а ключ файла оборачивается мастер-ключом профиля с помощью SecretBox. Заголовок и каждый блок аутентифицируются.

Подробности и границы модулей описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Два независимых сценария

Файловый сценарий повторяет привычную модель GpgEX: выбранный файл остаётся на месте, а рядом создаётся отдельный зашифрованный файл. Пока Clever PGP шифрует для собственного локального профиля. Выбор получателя по открытому ключу, подпись и несколько выбранных файлов будут добавлены после формирования ключевой пары и раздела контактов.

Контейнерный сценарий работает подобно VeraCrypt на уровне взаимодействия: Clever PGP создаёт один файл `.cpgv`, подключает его как отдельный диск, а пользователь копирует существующие файлы внутрь. Это собственный формат Clever PGP, не совместимый с VeraCrypt.

Формат контейнера v3 хранит данные независимыми аутентифицированными логическими блоками. Запись файла изменяет только соответствующие блоки; номер блока криптографически связан с его шифротекстом, поэтому перестановка или подмена обнаруживается. Метаданные файловой системы записываются в два чередующихся контрольных состояния. Новое состояние становится рабочим только после полной синхронизации, а при прерванной записи остаётся предыдущее завершённое состояние. Открытая временная папка на диске не создаётся. Старые форматы `.cpgv` не поддерживаются.
