# Архитектура Clever PGP v0.4

## Зафиксированные принципы

1. Криптографические операции полностью локальны и не зависят от сервера.
2. Программа распространяется бесплатно и не использует сервер лицензирования или активации.
3. Лицо — фактор биометрического управления доступом, но не источник криптографического ключа.
4. Мастер-ключ генерируется криптографически стойким генератором случайных чисел.
5. Отдельного recovery-файла нет. Во всех режимах создаётся парольный слот мастер-ключа; в режиме «только лицо» он служит аварийным локальным способом.
6. GUI, хранилище, криптографическое ядро и будущий биометрический backend разделены, чтобы перенести приложение на Ubuntu без переделки формата файлов.

## Поток разблокировки паролем

```text
мастер-пароль + уникальная соль
            ↓
          Argon2id
            ↓
   парольный ключ (KEK)
            ↓
аутентифицированная расшифровка
            ↓
случайный мастер-ключ профиля
```

SQLite хранит только соль, параметры Argon2id и зашифрованный мастер-ключ. После блокировки приложения копия мастер-ключа в объекте сессии перезаписывается. Python не даёт строгой гарантии удаления всех временных копий из памяти; это ограничение MVP и одна из причин будущего выделения критического кода в нативный модуль.

## Шифрование файла

```text
случайный ключ файла ── SecretBox(мастер-ключ) ──> ключ в заголовке
         │
         └── XChaCha20-Poly1305 secretstream ──> блоки шифротекста
```

Формат версии 1:

```text
magic | version | header_length | JSON header | record_length | record | ...
```

JSON содержит только идентификаторы алгоритмов, заголовок secretstream, обёрнутый ключ файла и размер блока. Исходное имя не помещается внутрь заголовка. Сырые байты заголовка используются как associated data каждого блока.

Последний блок имеет обязательный тег `FINAL`. Расшифрование выполняется во временный файл; целевой путь появляется только после проверки тега и отсутствия лишних данных.

## Границы модулей

- `biopgp.core.profile_service` — создание профиля, Argon2id, разблокировка сессии;
- `biopgp.core.storage` — SQLite и миграция схемы;
- `biopgp.core.file_crypto` — версия формата `.cpgp` и потоковая криптография;
- `biopgp.core.block_volume` — независимое аутентифицированное хранение логических блоков `.cpgv`;
- `biopgp.core.block_container` — дерево каталогов, экстенты файлов и чередующиеся состояния метаданных;
- `biopgp.core.container` — прежний компактный исследовательский формат, оставленный только для изолированных тестов и не используемый приложением;
- `biopgp.core.mount` — адаптер WinFsp/FUSE и жизненный цикл подключённого диска;
- `biopgp.core.winspd` — мост SCSI-команд WinSpd, отдельный фоновый процесс и системный формат блочного диска;
- `biopgp.core.windows_storage` — строгая идентификация нового диска Windows, форматирование, поиск буквы и безопасное отключение;
- `biopgp.core.disk_control` — аутентифицированный loopback-канал и защищённое состояние активного системного диска;
- `biopgp.core.windows_shell` — динамическое меню Проводника, ограниченное буквой активного системного диска;
- `biopgp.ui.main_window` — интерфейс без криптографических примитивов;
- `biopgp.shell` и `biopgp.ui.shell_dialog` — отдельный безопасный процесс для команды Проводника;
- будущий `biopgp.biometrics` — камера, embedding, liveness и политика совпадения;
- будущий `biopgp.key_protection` — Windows CNG/DPAPI/TPM и Linux Secret Service/TPM2.

## Интеграция с Проводником Windows

`install_context_menu.ps1` создаёт статические shell verbs в пользовательской ветке `HKCU\Software\Classes`. Команда запускается через `pythonw.exe`, поэтому консольное окно не появляется. Путь выбранного файла передаётся как отдельный заключённый в кавычки аргумент.

После подключения системного диска приложение создаёт отдельное пользовательское
shell-меню с условием `AppliesTo` по системному свойству `System.ItemPathDisplay`.
Условие содержит конкретную назначенную букву, поэтому команды не появляются у
обычных NTFS/exFAT-накопителей. При отключении удаляется только дерево
`CleverPGP.SystemMenu`; чужие обработчики Проводника не затрагиваются.
Меню содержит только уже работающие команды: открыть диск, открыть настройки
доступа Clever PGP и безопасно отключить диск. Настройки запускаются напрямую в
графическом процессе без `cmd.exe`; после разблокировки профиля пользователь
может изменить режим доступа, зарегистрировать лицо или сменить мастер-пароль.

Шифрование и расшифрование выполняются в отдельном процессе и отдельном рабочем потоке. Сбой этого процесса не влияет на Проводник. Исходный файл не удаляется; целевой файл появляется только после полной аутентифицированной проверки и атомарного переименования временного файла.

## Следующий этап: биометрический слот

Биометрический backend должен выдавать только решение об успешной локальной проверке. После него системное защищённое хранилище разрешает расшифровать дополнительную обёртку того же мастер-ключа. Шаблон лица хранится локально в зашифрованном виде; камера включается только на время регистрации или проверки.

## Изменение настроек доступа

Смена мастер-пароля не создаёт новый мастер-ключ и не перешифровывает файлы или
контейнеры. После проверки текущего пароля тот же случайный мастер-ключ
защищается новым независимо выработанным парольным ключом и новой солью. Запись
парольного слота заменяется одной транзакцией SQLite с контролем предыдущего
значения, поэтому параллельный процесс не может незаметно перезаписать более
новое состояние. Биометрический слот остаётся неизменным.

Режимы «Только лицо» и «Мастер-пароль + лицо» разрешается включить только после
успешной регистрации лица. В режиме «Только лицо» парольный ввод скрыт в обычном
сценарии, но остаётся доступен как явно выбранный аварийный способ — отдельный
recovery-файл не создаётся.

## Контейнер и виртуальный диск

Формат `.cpgv` версии 3 состоит из трёх слотов защищённого заголовка, двух областей метаданных и массива независимо шифруемых логических блоков размером 4096 байт. В заголовке находятся версия, геометрия диска, идентификатор и случайный ключ тома, защищённый мастер-ключом профиля.

```text
мастер-ключ профиля ──> защищённый случайный ключ тома
                                   │
          ┌────────────────────────┼─────────────────────────┐
          ↓                        ↓                         ↓
  метаданные A              метаданные B            логические блоки
  поколение N               поколение N+1           содержимого файлов
```

Для каждой операции записи формируются новый криптографический параметр блока и уникальный контекст поколения. Идентификатор тома, логический адрес и контекст поколения включаются в аутентифицируемые данные, поэтому повреждение, подмена, перестановка и возврат отдельного блока к прежней версии обнаруживаются при чтении. Перезапись использует копирование при записи: новый блок сохраняется до публикации новой карты размещения. Метаданные кодируют дерево каталогов, размеры и компактные экстенты файлов вместе с ожидаемым контекстом поколения.

Состояния метаданных чередуются. Каждое содержит монотонный номер поколения и контроль целостности всего состояния. Сначала записываются новые блоки, затем неактивное состояние метаданных, после чего выполняется принудительная синхронизация. Если процесс или питание прерваны, при следующем открытии выбирается последнее полностью проверенное поколение. Отдельный резерв блоков сохраняет возможность копирования при записи даже при полностью занятой пользовательской ёмкости; при длительной перезаписи заполненного диска безопасные контрольные состояния создаются порциями.

Увеличение блочного массива использует отдельные состояния заголовка
`committed → preparing → committed`. Новый рабочий размер публикуется только
после записи и принудительной синхронизации всех добавленных зашифрованных
нулевых блоков. Сбой на любой промежуточной стадии оставляет доступной прежнюю
подтверждённую ёмкость. Существующие блоки, идентификатор и ключ тома при этом не
изменяются. Уменьшение запрещено до появления доказанно безопасного анализа
занятых кластеров файловой системы.

На Windows собственная файловая система пока публикуется через WinFsp; на Ubuntu тот же файловый адаптер сможет использовать системный `/dev/fuse`. Открытые имена и содержимое не записываются во временный каталог. Старый компактный формат с сериализованной SQLite-файловой системой не поддерживается.

Мост WinSpd уже реализован как самостоятельный скрытый host-процесс. Он
обслуживает чтение, запись, принудительную синхронизацию и освобождение диапазонов
блоков; постоянный идентификатор диска берётся из защищённого заголовка. GUI
создаёт одноразовый запрос с мастер-ключом, защищённым DPAPI текущего пользователя,
а host удаляет запрос сразу после чтения. В командной строке передаётся только
путь к одноразовому запросу. Для команд Проводника host создаёт канал только на
loopback-интерфейсе и принимает команды после проверки случайного 256-битного
токена. Токен в локальном состоянии защищается DPAPI текущей учётной записи;
мастер-ключ в это состояние не записывается. Официальная проверочная утилита
WinSpd успешно выполняет случайные операции над исходной и упакованной версиями
Clever PGP.

Host запускается как отдельный процесс `CleverPGP.exe --winspd-host` (в среде
разработки — через `pythonw.exe`) и не принадлежит GUI через механизм
`multiprocessing`. Поэтому пользователь может выбрать в области уведомлений
«Закрыть Clever PGP — диск останется подключённым». Сам диск продолжает работать
до команды безопасного отключения из Проводника или следующего сеанса GUI.
При следующем запуске менеджер перечисляет защищённые записи текущего
пользователя и принимает состояние только после успешной аутентифицированной
команды `ping` соответствующему host. Поэтому повторно запущенный GUI видит уже
подключённый диск, не создаёт второй экземпляр и может отправить безопасную
команду отключения без прежнего process handle. Недействительные записи
удаляются вместе с устаревшим меню Проводника.

Установщик проверяет SHA-256 и подпись официального пакета WinSpd, включает
платформенную библиотеку в `CleverPGP.exe` и устанавливает драйвер вместе с
программой. До переключения пользовательского интерфейса остаются реальные
испытания подключения к Windows Storage Stack, форматирования NTFS/exFAT,
определения назначенной буквы и аварийного отключения. Текущий WinFsp-backend
сохраняется как безопасный рабочий вариант до прохождения этих испытаний.

Менеджер системного диска уже объединяет создание `.cpgv`, подключение
фонового процесса, поиск ровно одного нового устройства, форматирование и
повторное подключение ранее созданного тома по назначенной Windows букве.
Названия томов на русском, казахском и английском передаются в PowerShell в
Base64-представлении, поэтому пользовательский текст не интерполируется в
системную команду.

Пользовательский путь системного диска подключён к интерфейсу в изолированном
режиме `CLEVERPGP_DISK_BACKEND=winspd`. В нём окно создания передаёт выбранные
путь, ёмкость и название менеджеру жизненного цикла, который создаёт блочный
контейнер, подключает устройство, форматирует выбранную NTFS или exFAT и
возвращает назначенную Windows букву. Интерфейс рекомендует журналируемую NTFS
для постоянной работы в Windows и объясняет, что совместимая exFAT менее
устойчива к внезапному отключению. Минимальная ёмкость такого диска — 32 МиБ.
Без явного включения этого режима программа по-прежнему использует проверенный
WinFsp-backend.
Переключение режима по умолчанию и выпуск нового установщика допускаются только
после отдельной реальной проверки с UAC на тестовом временном диске.

Команда `--unmount` сначала проверяет служебный файл текущего WinFsp-диска, а
для системного NTFS/exFAT-диска находит защищённую запись текущего пользователя
и отправляет аутентифицированную команду его фоновому процессу. После
исчезновения буквы диска запись удаляется. Это позволяет использовать один
пункт безопасного отключения для обоих backend без передачи секретов через
командную строку.
