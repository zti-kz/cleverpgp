# Архитектура Clever PGP

## Модель доступа

Clever PGP не создаёт общий мастер-пароль приложения и не требует пароль при
установке или обычном запуске. Пароль принадлежит конкретному защищаемому
объекту:

- файл `.cpgp` шифруется и открывается своим паролем;
- обычный диск `.cpgv` создаётся и открывается своим паролем;
- внешний и скрытый диски внутри одного `.cpgv` имеют разные пароли;
- настройки языка и интерфейса не являются криптографическим профилем.

Пароль не используется непосредственно для шифрования пользовательских данных.
Для каждого файла или диска создаётся независимый случайный ключ. Из пароля с
уникальной солью и ресурсоёмкой функцией вырабатывается ключ доступа, которым
защищается случайный ключ объекта.

Это даёт переносимость: `.cpgp` и `.cpgv` можно открыть после переустановки или
на другом компьютере, если известен пароль объекта. Локальная база Clever PGP
для этого не требуется.

## Отдельный файл `.cpgp`

Текущий парольный формат имеет версию 3. Заголовок содержит:

- идентификатор формата и алгоритма;
- уникальную соль и закреплённые параметры выработки ключа;
- случайный ключ файла, защищённый ключом доступа;
- заголовок потокового аутентифицированного шифрования.

Файл обрабатывается блоками по 1 МиБ. Каждый блок аутентифицируется и связан с
заголовком как с дополнительными проверяемыми данными. Завершающий блок
обязателен. Неверный пароль, изменение заголовка, повреждение, усечение и
добавление данных обнаруживаются до публикации результата.

Расшифрованный результат сначала записывается во временный файл в каталоге
назначения и атомарно переименовывается только после полной проверки.
Оригинальный файл при шифровании не изменяется.

Команды Проводника запускают тот же `CleverPGP.exe` с явным действием и путём:

```text
CleverPGP.exe --shell encrypt "<путь>"
CleverPGP.exe --shell decrypt "<путь.cpgp>"
CleverPGP.exe --secure-delete "<путь>"
```

Обработчик не проверяет наличие локального профиля. Он запрашивает пароль файла,
показывает прогресс и блокирует закрытие окна на время операции.

## Цифровые ключи и получатели

Пользователь может создать несколько независимых пар ключей. Одна часть пары
используется для адресного шифрования, вторая — для цифровой подписи. Закрытые
части объединяются в аутентифицированный пакет и защищаются ключом доступа,
который вырабатывается из отдельного пароля ключа и уникальной соли. Локальная
база хранит только открытые части, параметры выработки и зашифрованный пакет.

Открытый самоподписанный ключ `.cpgk` можно передавать получателям. Защищённая
резервная копия `.cpgx` содержит закрытую часть только в зашифрованном виде.
Перед экспортом `.cpgk` или `.cpgx` пароль проверяется раскрытием закрытого
пакета. Импорт `.cpgx` также завершается только после проверки пароля и
математического соответствия открытой и закрытой частей. Открытый `.cpgk` не
является секретом и импортируется без пароля — иначе адресное шифрование по
модели PGP потребовало бы передачи секретного пароля получателю.

При ключевом шифровании создаётся один случайный ключ файла. Для каждого
получателя в заголовок помещается отдельный ключевой слот, защищённый его
открытым ключом. Отправитель автоматически включается в список получателей и
подписывает содержимое. Расшифрование возможно только соответствующим закрытым
ключом и его паролем.

## Защищённое удаление файла

Команда Проводника перезаписывает выбранный обычный файл тремя проходами,
принудительно сохраняет каждый проход, обнуляет длину, меняет имя и удаляет
каталожную запись. Операция всегда требует явного подтверждения. На HDD это
предназначено для уничтожения непосредственно адресуемого содержимого. На SSD,
в снимках, резервных копиях и файловых системах с копированием при записи
физическое уничтожение всех прежних копий программно не гарантируется.

## Зашифрованный диск `.cpgv`

Обычный диск состоит из защищённого заголовка и независимо шифруемых логических
блоков. Для каждого нового диска создаются случайный ключ доступа и отдельный
ключ тома. Парольный слот находится в самом `.cpgv`; общего ключа программы для
открытия диска нет.

При чтении и записи адрес блока, контекст поколения и шифротекст связаны кодом
аутентичности. Перестановка, подмена, повреждение и возврат блока к прежнему
состоянию обнаруживаются. Метаданные используют чередующиеся согласованные
состояния, поэтому прерванное обновление не публикует незавершённую структуру.

В Windows быстрый backend создаёт виртуальное блочное устройство через WinSpd.
Windows использует на нём NTFS или exFAT. Шифруются только затронутые блоки;
контейнер целиком при каждом копировании не перешифровывается. Командные окна
скрыты, этапы отображаются в графическом прогрессе.

После подключения диск обслуживает отдельный скрытый host-процесс. Закрытие GUI
не отключает диск. Контекстное меню активной буквы публикуется только пока жив
защищённый канал управления этим диском.

Каждый дополнительный `.cpgv` запускает независимый процесс подключения без
захвата уже опубликованного управляющего канала. Поэтому несколько контейнеров
могут одновременно иметь разные буквы и собственные команды отключения.

## Скрытый диск

В формате скрытого диска один `.cpgv` содержит внешний и скрытый тома. Пароль
определяет, какой защищённый заголовок будет аутентифицирован и какой том будет
подключён. Заголовок внешнего тома автоматически ограничивает видимую ему
область, поэтому интерфейс не предлагает отдельный флажок защиты скрытой
области.

## Биометрическое управление

Лицо не является криптографическим ключом и из биометрического шаблона ключ не
вырабатывается. Биометрический доступ должен добавляться только после успешного
входа в выбранный диск по его паролю. После локальной проверки лица и liveness
системное защищённое хранилище разрешает использовать дополнительную обёртку
случайного ключа именно этого диска.

Глобальной регистрации лица при установке или запуске нет. Отдельный recovery
key не создаётся. Пароль диска остаётся переносимым способом доступа, если
камера недоступна. Реализация привязки биометрии к отдельному диску является
следующим этапом после стабилизации парольных файлов и дисков.

## Локальные данные

SQLite используется для языка, настроек интерфейса, открытых ключей получателей,
зашифрованных пакетов локальных цифровых ключей и в будущем для локальных
описателей биометрического доступа. Пароли файлов, дисков и цифровых ключей,
случайные ключи объектов и расшифрованные пользовательские данные в SQLite не
сохраняются.

Ключи, необходимые подключённому диску, находятся в памяти отдельного
host-процесса только на время подключения. Python не гарантирует полное
физическое стирание всех временных копий; критические операции должны в
дальнейшем переноситься в минимальный нативный модуль с блокируемой памятью.

## Границы безопасности

Clever PGP не шифрует операционную систему, загрузчик, физический накопитель или
системный раздел. Backend принимает только обычные файлы-контейнеры `.cpgv`.
Операция форматирования допускается только для только что созданного
виртуального устройства после повторной проверки его идентичности и размера.

Проект остаётся исследовательским MVP и не проходил независимый
криптографический аудит. Важные данные должны иметь отдельные резервные копии.
