# Блочный зашифрованный диск Clever PGP

## Причина замены компактного формата

Предыдущий формат `.cpgv` хранил собственную файловую систему в базе SQLite в
оперативной памяти. При дописывании очередного фрагмента файла создаётся новая
копия уже накопленных данных, а при синхронизации вся база сериализуется и
повторно шифруется. Время записи поэтому растёт нелинейно. Такой формат пригоден
только для функционального прототипа и не должен использоваться для больших
файлов, фильмов или рабочих дисков.

Текущий формат версии 3 представляет содержимое как массив логических блоков.
Собственная файловая система Clever PGP хранит каталоги и компактные экстенты в
двух чередующихся областях метаданных. При чтении и записи преобразуются только
затронутые блоки. WinFsp публикует эту файловую систему в Windows без изменения
работающих компонентов отдельного шифрования файлов.

Системный backend представляет массив блоков через WinSpd как SCSI-диск и
обрабатывает чтение, запись, flush и unmap в отдельном процессе. Windows создаёт
на нём обычный раздел NTFS или exFAT, поэтому копирование использует системное
кэширование, очереди ввода-вывода и параллельную обработку. Официальный
`stgtest` проверяет случайные операции и совпадение записанных данных; такая же
проверка встроена в цикл сборки упакованного EXE.

Старые форматы не переносятся и не поддерживаются, как было решено
ранее.

## Компоненты Windows MVP

1. `CleverPGP.exe` показывает профиль, создание диска и компактное окно
   разблокировки. После подключения окно скрывается в область уведомлений.
   При создании быстрый системный диск Windows предлагается первым, если
   WinSpd установлен; существующий WinFsp-вариант остаётся доступным в том же
   диалоге и не заменяется.
2. Фоновый процесс подключения продолжает обслуживать диск после закрытия
   графического окна. Явное отключение выполняется через меню диска или значок
   в области уведомлений.
3. Системный компонент блочного устройства передаёт запросы чтения и записи
   фоновому процессу. WinFsp остаётся только у текущего прототипа: это интерфейс
   файловой системы, а не зашифрованного блочного устройства.
4. Защищённый локальный канал управления связывает контекстное меню, интерфейс
   и фоновый процесс. Через него выполняются открытие, отключение и получение
   состояния диска. Секретные значения в журнал не записываются.

Текущая реализация канала управления слушает только `127.0.0.1` и проверяет
случайный токен перед выполнением `ping` или `stop`. Копия токена в каталоге
состояния защищена DPAPI текущего пользователя и связана с идентификатором тома.
Запись содержит букву диска, порт и идентификатор процесса, но не содержит
мастер-ключ или ключ шифрования тома. Путь контейнера сохраняется отдельно в
этой же записи только в виде значения, защищённого DPAPI текущего пользователя;
открытый путь в JSON не публикуется. Упакованный runtime-тест обязан проверить
не только 2 000 операций WinSpd, но и остановку процесса внешней командой.

Сам host не является дочерним `multiprocessing`-процессом GUI. Для запуска GUI
создаёт одноразовый DPAPI-защищённый запрос, а в аргументах host находится только
путь к нему. После получения ключа host немедленно удаляет запрос и публикует
DPAPI-защищённый ответ готовности. Благодаря этому закрытие GUI не вызывает
автоматическое ожидание или завершение host-процесса.

## Формат `.cpgv` версии 3

Контейнер полностью размещается на выбранном накопителе. Перед созданием
проверяются свободное место, предельный размер файла и возможность выделения
заданного объёма.

```text
Основной заголовок и резервная копия
Область служебных данных и журнала
Секторы внешнего диска
Неиспользованная область, заполненная случайными данными
Секторы скрытого диска (если он создан)
Скрытый заголовок и его резервная копия
```

Для каждого диска формируется независимый случайный ключ шифрования. Пароль или
успешная локальная проверка лица только разрешают расшифрование заголовка. Лицо
не преобразуется в ключ. Замена пароля переупаковывает заголовок и не требует
повторного шифрования всех секторов.

Основной режим первого блочного MVP использует независимое аутентифицированное
шифрование каждого логического блока размером 4096 байт. При каждой перезаписи
блока формируется новый случайный параметр, а номер блока, идентификатор диска и
уникальный контекст поколения записи включаются в аутентифицируемые данные.
Перестановка, подмена, возврат к прежней версии или повреждение блока поэтому
обнаруживаются при чтении. Физическая запись содержит 24 байта
случайного параметра и 16 байт кода аутентификации сверх размера блока.
Помимо выбранной пользователем ёмкости контейнер выделяет небольшой резерв для
копирования при записи. Благодаря ему существующий блок не перезаписывается до
публикации нового согласованного состояния даже при заполненном диске.

Измерение реализации на 32 МБ показало около 86 МиБ/с внутри файлового адаптера
против 18 МиБ/с у прежнего компактного формата на той же машине. Проверка через
реально подключённую букву диска Windows показала около 89 МиБ/с записи и
68 МиБ/с чтения. Результат зависит от накопителя, процессора, антивируса и
размера запроса и не является гарантией скорости на другом компьютере.

Дополнительный метод можно добавлять только после реализации в проверенной
нативной библиотеке, тестирования совместимости и сравнительного измерения
скорости. Например, режим XTS широко применяется для накопителей и хорошо
ускоряется аппаратно, но сам по себе не обеспечивает аутентификацию секторов.
Это различие должно быть явно отражено в кратком описании выбора. Выбранный
метод нельзя мгновенно поменять у существующего диска: требуется полное
автономное преобразование всех секторов.

Заголовки также аутентифицируются. Повреждение заголовка или неверный пароль
приводят к отказу подключения. Формат `.cpgp` сохраняется для отдельной защиты
пользовательских документов.

Низкоуровневый блочный формат использует три независимых аутентифицируемых
слота заголовка. При увеличении отключённого контейнера сохраняются:

1. последнее подтверждённое состояние;
2. подписанное намерение увеличить число блоков;
3. новое подтверждённое состояние после записи и синхронизации всех блоков.

Если питание или процесс прерваны, новый размер не публикуется, а открывается
последняя полностью подтверждённая ёмкость. Частично дописанный хвост разрешён
только при наличии соответствующего аутентифицированного намерения и удаляется
перед повторной попыткой. Произвольные данные после конца контейнера приводят к
отказу открытия. После успешного увеличения прежний рабочий слот выводится из
обращения, поэтому простое усечение файла не возвращает старую ёмкость.

## Скрытый диск

Скрытый диск не является вторым видимым разделом. Один файл контейнера содержит
два независимых заголовка и две файловые системы:

- внешний пароль открывает внешний диск;
- скрытый пароль открывает скрытый диск;
- по внешнему виду контейнера нельзя определить наличие скрытого диска;
- одновременно подключается только один из них.

Разрежённый или динамический файл несовместим с правдоподобным сокрытием,
поэтому контейнер со скрытым диском выделяется полностью и заполняется
криптографически случайными данными. Запись во внешний диск может уничтожить
скрытую область. Безопасные режимы: внешний диск только для чтения либо защита
границ скрытой области после дополнительного ввода скрытого пароля. Наличие
этого пароля не сохраняется после отключения.

Реализован внутренний блочный слой скрытого диска. Его логические блоки имеют
собственную аутентификацию и размещаются непрерывным непрозрачным потоком в
хвостовой области внешнего диска. При записи сначала защищается скрытый блок,
затем изменившиеся блоки внешнего слоя снова аутентифицируются его независимым
ключом. Поэтому скрытые данные не нарушают проверку целостности внешнего
контейнера, а неверный скрытый ключ, подмена или повреждение обнаруживаются.

Также реализована защитная внешняя блочная проекция: запись вне скрытой области
разрешена, а первая попытка затронуть её отклоняется и переводит внешний диск в
режим «только чтение» до отключения. Это состояние не пытается продолжить запись
после частично предотвращённой операции.

Этот слой пока не публикуется пользователю. До включения функции в интерфейс
нужны новый непрозрачный формат заголовков, независимое получение ключей из двух
паролей, проверка свободной хвостовой области файловой системы и подключение
выбранной паролем проекции через WinSpd. Текущий открытый заголовок формата v3
не обеспечивает правдоподобное отрицание наличия скрытого диска.

Начата реализация заголовка формата v4. В начале файла резервируются две
одинаковые области фиксированного размера: внешняя и потенциально скрытая.
Каждая содержит по две независимо зашифрованные копии, а незанятые байты
заполняются криптографически случайными данными. Сигнатура формата, назначение,
названия, геометрия и ключи находятся только внутри аутентифицированного
шифротекста. Открытых JSON-полей и признака заполненности скрытой области нет.

При вводе пароля программа сначала проверяет обе копии внешней области. Если
они не аутентифицируются, тем же способом проверяется скрытая область. Внешний
заголовок содержит только ключ внешнего слоя. Скрытый заголовок содержит ключ
того же внешнего слоя, отдельный ключ скрытых блоков и границы их области.
Пароли обязаны различаться, а сообщение при неверном пароле, случайной пустой
скрытой области и повреждённом заголовке одинаково. Формирование ключа для
каждой копии намеренно требует заметных вычислений и памяти; интерфейс должен
показывать общий прогресс проверки.

За резервом заголовков уже реализован внешний массив независимо
аутентифицируемых блоков v4. Один метод открытия возвращает внешнюю или скрытую
блочную проекцию в зависимости от подтверждённого заголовка. Отдельный защищённый
режим внешнего диска принимает скрытый пароль, узнаёт границы скрытой области и
после первой предотвращённой записи оставляет внешний диск только для чтения до
отключения.

Формат v4 пока является внутренней разработкой и не заменяет рабочий v3 в
выпуске 0.7.0. Создание скрытого слоя разрешено только через внутренний метод,
который требует явно указанную, заранее проверенную свободную область. До
появления надёжной проверки карты занятых кластеров NTFS/exFAT эта операция не
показывается в интерфейсе: запись в просто предполагаемый свободный хвост могла
бы повредить внешние файлы. Следующий шаг — выполнить такую проверку и связать
выбранную блочную проекцию с WinSpd.

Для нового, ещё не форматированного системного диска предусмотрен более строгий
сценарий: полностью создать внешний слой, разместить скрытый слой в его хвосте,
подключить внешний слой только с активной защитой скрытой области и лишь затем
передать виртуальное устройство форматированию Windows. Если форматирование
пытается затронуть скрытую область, защита отклоняет запись, весь образ считается
незавершённым и удаляется. Такой порядок соответствует опубликованной
[последовательности VeraCrypt для создания скрытого тома без файловой системы](https://veracrypt.io/en/Command%20Line%20Usage%20for%20Unix.html).
Для добавления скрытого тома в уже используемый внешний диск всё равно нужна
карта кластеров: Windows предоставляет её через
[`FSCTL_GET_VOLUME_BITMAP`](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_volume_bitmap),
но снимок может устареть сразу после чтения, поэтому том должен быть отключён от
обычных записей на всём протяжении проверки и создания.

Внутренний Windows-менеджер уже выполняет защищённую последовательность для
нового образа: создаёт обе проекции, готовит их таблицы разделов, форматирует
внешний диск только через защитную обёртку, отключает его и затем форматирует
скрытый. После каждой операции проверяется, что самостоятельный WinSpd-host не
остановился из-за предотвращённой записи. До завершения обеих файловых систем
образ считается незавершённым и при ошибке удаляется. Пароли остаются в GUI;
host получает только DPAPI-защищённый одноразовый пакет с уже выбранным
материалом заголовка.

## Команды контекстного меню

В главном окне остаются только создание и подключение диска. Контекстное меню
подключённого диска постепенно получает только работающие команды:

- открыть диск;
- безопасно отключить диск;
- сведения о размере, файловой системе и методе защиты;
- увеличить размер отключённого контейнера и затем расширить файловую систему;
- заменить пароль заголовка;
- настроить разрешение по лицу;
- выполнить автономное преобразование метода защиты.

Для системного диска работающий набор — «Открыть», «Сведения о диске»,
«Настройки доступа», «Увеличить диск» и «Безопасно отключить». Он регистрируется в пользовательской
ветке Windows только для назначенной буквы диска через AQS-условие
`System.ItemPathDisplay` и удаляется после отключения. Сведения показываются в
компактном окне без раскрытия главного интерфейса и содержат только ёмкость,
файловую систему, тип подключения и описание метода защиты. Остальные пункты не
добавляются, пока соответствующая операция не реализована и не проверена.

Первичное форматирование WinSpd-диска выполняет отдельный минимальный
UAC-процесс. Он не получает криптографические ключи: одноразовый запрос содержит
только защищённый токен работающего host, точный снимок нового виртуального
устройства, выбранную файловую систему и название. Перед разрушительной
командой помощник подтверждает host и повторно проверяет идентичность, геометрию,
MBR и отсутствие признаков системного или загрузочного диска.

Увеличение блочного контейнера уже реализовано без перешифрования прежних
блоков. Для системного диска подготовлена полная последовательность:
идентификация активного диска, безопасное отключение, увеличение контейнера,
повторное подключение и расширение раздела NTFS. Windows выполняет последний
шаг в отдельном минимальном процессе с запросом UAC. В него не передаются
мастер-пароль, мастер-ключ, ключ тома или биометрические данные.

Перед изменением раздела процесс повторно проверяет аутентифицированный канал
работающего host, букву, идентификатор, серийный номер, размер и геометрию диска,
запрещает загрузочные и системные диски и требует единственный раздел NTFS.
Встроенные средства Windows поддерживают такое расширение только для NTFS.
Диск exFAT можно создавать и использовать, но его увеличение отключено, чтобы
не форматировать и не переносить данные скрытно от пользователя.
Ограничение и требования к смежному нераспределённому пространству описаны в
официальной документации Microsoft для команд
[`extend`](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/extend)
и
[`Resize-Partition`](https://learn.microsoft.com/en-us/powershell/module/storage/resize-partition).

Диалог использует один горизонтальный ползунок от текущей ёмкости до физически
доступного места на накопителе контейнера и показывает проценты всех стадий.
Команда увеличения публикуется только в динамическом меню активного системного
диска и запускает компактное окно аутентификации. Одноразовый запрос расширения
защищён DPAPI и HMAC, удаляется после чтения и принимается только процессом с
правами администратора. Уменьшение размера опаснее увеличения и не включается
в первый выпуск.

## Использование VeraCrypt как технического эталона

Официальный репозиторий VeraCrypt сохранён отдельно в `work/reference` и не
смешивается с исходным кодом Clever PGP. Изучаются модель блочного ввода-вывода,
жизненный цикл подключения, работа скрытого тома и защита его границ.

Хотя Clever PGP теперь распространяется как свободное программное обеспечение,
прямое включение кода VeraCrypt создало бы производное произведение по
TrueCrypt License 3.0 и добавило бы отдельные требования к уведомлениям,
наименованию и распространению. Поэтому блочный компонент Clever PGP
реализуется независимо на основе опубликованных стандартов и библиотек с
совместимыми лицензиями. WinSpd разрешается использовать с FLOSS-программой при
сохранении обязательного уведомления об авторских правах и ссылки на проект.
Перед выпуском системного компонента всё равно требуются аудит лицензий,
тестирование драйвера и цифровая подпись Windows.

## Безопасная проверка системного диска

Сценарий `scripts/run_winspd_windows_check.ps1` предназначен только для
разработки и показывает стандартный запрос UAC. Он устанавливает официальный
пакет WinSpd после проверки SHA-256, создаёт временный контейнер размером
128 МиБ и запоминает список дисков до подключения. Форматирование разрешается,
только если после подключения появился ровно один новый диск с именем WinSpd
или CleverPGP и точным ожидаемым размером.

Стенд запускает тот же самостоятельный `WinSpdHostManager`, который использует
графический интерфейс, а не прежний дочерний `multiprocessing`-процесс. Поэтому
реальная проверка одновременно охватывает DPAPI-запуск host, Windows Storage
Stack, форматирование и внешнее безопасное отключение.

Перед `Format-Volume` параметры повторно проверяются средствами Windows:
номер, имя, размер, тип MBR, единственный раздел и его смещение 1 МиБ. Затем на
временный NTFS-диск записывается и считывается 8 МиБ случайных данных с
проверкой SHA-256. После отключения проверяется исчезновение номера диска.
Любое несоответствие прерывает сценарий до форматирования.

Тот же менеджер можно испытать через графический интерфейс, запустив среду
разработки с переменной `CLEVERPGP_DISK_BACKEND=winspd`. Диалог создания в этом
режиме позволяет выбрать NTFS или exFAT и передаёт выбор непосредственно в
строго проверенную операцию Windows `Format-Volume`. Сам интерфейс не должен
постоянно работать с повышенными правами: для изменения размера подготовлен
отдельный минимальный процесс, который получает только одноразовый запрос с
публичной геометрией выбранного диска и повторно проверяет цель после UAC.
