# Блочный зашифрованный диск Clever PGP

## Причина замены компактного формата

Предыдущий формат `.cpgv` хранил собственную файловую систему в базе SQLite в
оперативной памяти. При дописывании очередного фрагмента файла создаётся новая
копия уже накопленных данных, а при синхронизации вся база сериализуется и
повторно шифруется. Время записи поэтому растёт нелинейно. Такой формат пригоден
только для функционального прототипа и не должен использоваться для больших
файлов, фильмов или рабочих дисков.

Текущий формат версии 3 представляет содержимое как массив логических блоков.
Собственная файловая система Clever PGP хранит каталоги и компактные экстенты в
двух чередующихся областях метаданных. При чтении и записи преобразуются только
затронутые блоки. WinFsp публикует эту файловую систему в Windows без изменения
работающих компонентов отдельного шифрования файлов.

Системный прототип уже представляет массив блоков через WinSpd как SCSI-диск и
обрабатывает чтение, запись, flush и unmap в отдельном процессе. Официальный
`stgtest` проверяет случайные операции и совпадение записанных данных; такая же
проверка встроена в цикл сборки упакованного EXE. Следующий контрольный этап —
подключение к Windows Storage Stack и штатное создание NTFS или exFAT. После
него копирование сможет использовать системное кэширование, очереди
ввода-вывода и параллельную обработку.

Старые форматы не переносятся и не поддерживаются, как было решено
ранее.

## Компоненты Windows MVP

1. `CleverPGP.exe` показывает профиль, создание диска и компактное окно
   разблокировки. После подключения окно скрывается в область уведомлений.
2. Фоновый процесс подключения продолжает обслуживать диск после закрытия
   графического окна. Явное отключение выполняется через меню диска или значок
   в области уведомлений.
3. Системный компонент блочного устройства передаёт запросы чтения и записи
   фоновому процессу. WinFsp остаётся только у текущего прототипа: это интерфейс
   файловой системы, а не зашифрованного блочного устройства.
4. Защищённый локальный канал управления связывает контекстное меню, интерфейс
   и фоновый процесс. Через него выполняются открытие, отключение и получение
   состояния диска. Секретные значения в журнал не записываются.

Текущая реализация канала управления слушает только `127.0.0.1` и проверяет
случайный токен перед выполнением `ping` или `stop`. Копия токена в каталоге
состояния защищена DPAPI текущего пользователя и связана с идентификатором тома.
Запись содержит букву диска, порт и идентификатор процесса, но не содержит
мастер-ключ или ключ шифрования тома. Упакованный runtime-тест обязан проверить
не только 2 000 операций WinSpd, но и остановку процесса внешней командой.

Сам host не является дочерним `multiprocessing`-процессом GUI. Для запуска GUI
создаёт одноразовый DPAPI-защищённый запрос, а в аргументах host находится только
путь к нему. После получения ключа host немедленно удаляет запрос и публикует
DPAPI-защищённый ответ готовности. Благодаря этому закрытие GUI не вызывает
автоматическое ожидание или завершение host-процесса.

## Формат `.cpgv` версии 3

Контейнер полностью размещается на выбранном накопителе. Перед созданием
проверяются свободное место, предельный размер файла и возможность выделения
заданного объёма.

```text
Основной заголовок и резервная копия
Область служебных данных и журнала
Секторы внешнего диска
Неиспользованная область, заполненная случайными данными
Секторы скрытого диска (если он создан)
Скрытый заголовок и его резервная копия
```

Для каждого диска формируется независимый случайный ключ шифрования. Пароль или
успешная локальная проверка лица только разрешают расшифрование заголовка. Лицо
не преобразуется в ключ. Замена пароля переупаковывает заголовок и не требует
повторного шифрования всех секторов.

Основной режим первого блочного MVP использует независимое аутентифицированное
шифрование каждого логического блока размером 4096 байт. При каждой перезаписи
блока формируется новый случайный параметр, а номер блока, идентификатор диска и
уникальный контекст поколения записи включаются в аутентифицируемые данные.
Перестановка, подмена, возврат к прежней версии или повреждение блока поэтому
обнаруживаются при чтении. Физическая запись содержит 24 байта
случайного параметра и 16 байт кода аутентификации сверх размера блока.
Помимо выбранной пользователем ёмкости контейнер выделяет небольшой резерв для
копирования при записи. Благодаря ему существующий блок не перезаписывается до
публикации нового согласованного состояния даже при заполненном диске.

Измерение реализации на 32 МБ показало около 86 МиБ/с внутри файлового адаптера
против 18 МиБ/с у прежнего компактного формата на той же машине. Проверка через
реально подключённую букву диска Windows показала около 89 МиБ/с записи и
68 МиБ/с чтения. Результат зависит от накопителя, процессора, антивируса и
размера запроса и не является гарантией скорости на другом компьютере.

Дополнительный метод можно добавлять только после реализации в проверенной
нативной библиотеке, тестирования совместимости и сравнительного измерения
скорости. Например, режим XTS широко применяется для накопителей и хорошо
ускоряется аппаратно, но сам по себе не обеспечивает аутентификацию секторов.
Это различие должно быть явно отражено в кратком описании выбора. Выбранный
метод нельзя мгновенно поменять у существующего диска: требуется полное
автономное преобразование всех секторов.

Заголовки также аутентифицируются. Повреждение заголовка или неверный пароль
приводят к отказу подключения. Формат `.cpgp` сохраняется для отдельной защиты
пользовательских документов.

## Скрытый диск

Скрытый диск не является вторым видимым разделом. Один файл контейнера содержит
два независимых заголовка и две файловые системы:

- внешний пароль открывает внешний диск;
- скрытый пароль открывает скрытый диск;
- по внешнему виду контейнера нельзя определить наличие скрытого диска;
- одновременно подключается только один из них.

Разрежённый или динамический файл несовместим с правдоподобным сокрытием,
поэтому контейнер со скрытым диском выделяется полностью и заполняется
криптографически случайными данными. Запись во внешний диск может уничтожить
скрытую область. Безопасные режимы: внешний диск только для чтения либо защита
границ скрытой области после дополнительного ввода скрытого пароля. Наличие
этого пароля не сохраняется после отключения.

## Команды контекстного меню

В главном окне остаются только создание и подключение диска. Контекстное меню
подключённого диска постепенно получает только работающие команды:

- открыть диск;
- безопасно отключить диск;
- сведения о размере, файловой системе и методе защиты;
- увеличить размер отключённого контейнера и затем расширить файловую систему;
- заменить пароль заголовка;
- настроить разрешение по лицу;
- выполнить автономное преобразование метода защиты.

Для системного диска первый работающий набор — «Открыть» и «Безопасно
отключить». Он регистрируется в пользовательской ветке Windows только для
назначенной буквы диска через AQS-условие `System.ItemPathDisplay` и удаляется
после отключения. Остальные пункты не добавляются, пока соответствующая операция
не реализована и не проверена.

Уменьшение размера опаснее увеличения и не включается в первый выпуск. Команды,
которые ещё не реализованы безопасно, не должны появляться как фиктивные кнопки.

## Использование VeraCrypt как технического эталона

Официальный репозиторий VeraCrypt сохранён отдельно в `work/reference` и не
смешивается с исходным кодом Clever PGP. Изучаются модель блочного ввода-вывода,
жизненный цикл подключения, работа скрытого тома и защита его границ.

Хотя Clever PGP теперь распространяется как свободное программное обеспечение,
прямое включение кода VeraCrypt создало бы производное произведение по
TrueCrypt License 3.0 и добавило бы отдельные требования к уведомлениям,
наименованию и распространению. Поэтому блочный компонент Clever PGP
реализуется независимо на основе опубликованных стандартов и библиотек с
совместимыми лицензиями. WinSpd разрешается использовать с FLOSS-программой при
сохранении обязательного уведомления об авторских правах и ссылки на проект.
Перед выпуском системного компонента всё равно требуются аудит лицензий,
тестирование драйвера и цифровая подпись Windows.

## Безопасная проверка системного диска

Сценарий `scripts/run_winspd_windows_check.ps1` предназначен только для
разработки и показывает стандартный запрос UAC. Он устанавливает официальный
пакет WinSpd после проверки SHA-256, создаёт временный контейнер размером
128 МиБ и запоминает список дисков до подключения. Форматирование разрешается,
только если после подключения появился ровно один новый диск с именем WinSpd
или CleverPGP и точным ожидаемым размером.

Стенд запускает тот же самостоятельный `WinSpdHostManager`, который использует
графический интерфейс, а не прежний дочерний `multiprocessing`-процесс. Поэтому
реальная проверка одновременно охватывает DPAPI-запуск host, Windows Storage
Stack, форматирование и внешнее безопасное отключение.

Перед `Format-Volume` параметры повторно проверяются средствами Windows:
номер, имя, размер, тип MBR, единственный раздел и его смещение 1 МиБ. Затем на
временный NTFS-диск записывается и считывается 8 МиБ случайных данных с
проверкой SHA-256. После отключения проверяется исчезновение номера диска.
Любое несоответствие прерывает сценарий до форматирования.

После успешной системной проверки тот же менеджер можно испытать через
графический интерфейс, запустив среду разработки с переменной
`CLEVERPGP_DISK_BACKEND=winspd` из окна PowerShell с правами администратора.
Диалог создания в этом режиме позволяет выбрать NTFS или exFAT и передаёт
выбор непосредственно в строго проверенную операцию Windows `Format-Volume`.
Это временный режим разработки: обычный запуск Clever PGP продолжает
использовать WinFsp, а финальная версия должна вынести привилегированные
операции в отдельный минимальный фоновый компонент, чтобы весь интерфейс не
работал с повышенными правами.
